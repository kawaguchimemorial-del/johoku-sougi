## 3. データモデル拡張（`data/plans.ts` / `data/areas.ts`）

方針: ページの本文は**データ側**に持ち、`app/plan/[plan]/page.tsx` / `app/area/[area]/page.tsx` はデータを描画するだけにする（既存方針を踏襲）。

### 3.1 `Plan` 型に追加

```ts
export type PlanSection = {
  heading: string;        // H2
  paragraphs: string[];
  list?: string[];
  table?: { caption?: string; headers: string[]; rows: string[][] }; // columns.ts の ColumnTable と同じ形でよい
};

export type PlanAreaNote = {
  areaSlug: "kita-ku" | "itabashi-ku" | "adachi-ku";
  heading: string;        // 例: "北区から一日葬を行う場合"
  paragraphs: string[];   // その区固有の内容（利用斎場・移動・所要時間・区の制度との関係）
  halls: string[];        // その区から使う斎場 slug（内部リンク生成用）
};

// Plan に追加
sections: PlanSection[];        // 本文セクション（流れ・費用の内訳・向いている方・注意点）
areaNotes: PlanAreaNote[];      // 区ごとの記述（H2 を区名込みにする＝「北区 一日葬」の直接回答）
faq: { question: string; answer: string }[];  // 5〜7問。FAQPage JSON-LD に使う
relatedColumns: string[];       // 関連コラム slug（columns.ts の slug）
```

### 3.2 `Area` 型に追加

```ts
export type AreaSection = {
  heading: string;        // H2（クエリ語を含める。例: "北区の通夜・告別式の一般的な流れ"）
  paragraphs: string[];
  list?: string[];
  table?: { caption?: string; headers: string[]; rows: string[][] };
};

// Area に追加
sections: AreaSection[];
faq: { question: string; answer: string }[];   // 5〜7問。FAQPage JSON-LD に使う
relatedColumns: string[];
```

### 3.3 描画側の変更点

- `app/plan/[plan]/page.tsx`: `sections` → `areaNotes` → `faq`（`<details>` ではなく見出し＋本文で全文表示。AIO・FAQPage のため）→ 関連コラム → 既存の「あわせてご覧ください」 → CTA。
- `app/area/[area]/page.tsx`: intro → 「利用できる斎場」→ `sections` → プラン一覧（**PlanCard のリンク文言は変えない**）→ 式場一覧 → `faq` → 関連コラム → CTA。
- FAQ は `faqLd()`（`lib/jsonld.ts` に既存）を使い、`JsonLd` に BreadcrumbList と並べて出力。
- 目次（ページ内リンク）は**不要**。H2 の数が7〜9になるので、モバイルで冗長になる。

## 4. P1: `/plan/one-day-funeral/`（一日葬）— 最優先

### 4.1 title / description（`generateMetadata` の固定テンプレートを、プラン個別の `metaTitle` / `metaDescription` で上書きできるようにする）

- title（現状）: `一日葬｜北区・板橋区・戸田斎場での一日葬相談`
- title（案）: **`北区・板橋区の一日葬｜流れ・費用目安・戸田斎場での進め方`**
  - 先頭に「北区・板橋区の一日葬」を置く（実クエリ語順「北区 一日葬」に合わせる）
- description（案）: `北区・板橋区で一日葬をご検討の方へ。通夜を行わず一日でお見送りする流れ、費用の目安（税込・内容により変動）、火葬場併設の戸田斎場を利用する場合の進め方を、城北セレモニーサポートセンター（運営・施行：川口典礼）がご説明します。24時間365日受付。`
- H1: `一日葬` → **`北区・板橋区の一日葬`**（PageHero の title）。lead は現状維持。

### 4.2 追加する本文セクション（`sections`）— 各H2は見出しにクエリ語を自然に含める

1. **一日葬とは（通夜を行わない一日のお見送り）** — 2段落。既存 description 3段落を統合。
2. **一日葬の当日の流れ（戸田斎場の例）** — 時間軸の表。`headers: ["時間の目安","内容"]`、rows: 出棺／式場着／告別式／出棺・火葬／収骨／（会食の有無）。「火葬場の混雑により前後する」旨を注記。
3. **一日葬の費用の内訳と目安** — 表。プラン費用（496,000円・税込目安）に**含まれるもの／別途になるもの**を分ける。別途: 式場使用料・火葬料金・宗教者へのお礼・返礼品・飲食費。→ `priceNotes` を必ず併記。戸田斎場の火葬料・式場料は `data/halls.ts` に無ければ「施設ページ参照」リンクのみ（**数値をでっちあげない**）。
4. **一日葬が向いている方・向かない場合** — list 各3〜4項目。「向かない場合」も書く（信頼感・E-E-A-T）。
5. **一日葬で気をつけたいこと** — 宗教者（菩提寺）への事前相談、参列者への案内文、火葬場の予約状況、安置日数。list 4項目。
6. **家族葬・火葬式との違い** — 3列比較表（一日葬／家族葬／火葬式・直葬）：日数・通夜・告別式・費用目安・向いている方。他プランへの内部リンク。

### 4.3 `areaNotes`（区別セクション。ここが「北区 一日葬」「板橋区 一日葬」への直接回答）

- **北区から一日葬を行う場合**（H2）: 利用斎場は戸田斎場が中心、北区セレモニーホールも選択肢。北区各エリア（赤羽・王子・十条・田端など）からの移動感（所要時間の目安は書けるものだけ。不明なら「車で30分前後」のような断定を避け「お電話でご案内」）。区の葬祭費（国保）の存在に触れ `/column/subsidy-funeral/` へリンク。`halls: ["toda-saijo","kita-ceremony-hall"]`
- **板橋区から一日葬を行う場合**（H2）: 戸田斎場・舟渡斎場が中心、蓮根レインボーホールも選択肢。板橋区は舟渡斎場が区内なので「区内で完結できる」点を書く。`halls: ["toda-saijo","funado-saijo","renkon-rainbow-hall"]`
- **足立区から一日葬を行う場合**（H2）: 町屋斎場（荒川区所在）を中心に。**足立区内に施設があるように書かない**。`halls: ["machiya-saijo"]`

### 4.4 `faq`（6問。FAQPage JSON-LD）

例（回答は2〜3文、価格は「目安・税込・変動」を守る）:
- 北区で一日葬をする場合、どの斎場を使うことが多いですか？
- 板橋区で一日葬をする場合、舟渡斎場と戸田斎場のどちらがよいですか？
- 一日葬の費用は総額でいくらくらいになりますか？（→目安＋別途費目＋個別見積り）

- 一日葬の日程はどのくらいで決まりますか？（→火葬場の空き次第）

- 使用禁止語: 最安／激安／必ず／絶対／追加費用なし／No.1／どこよりも安い／公式／公認／北区民のみ／板橋区民のみ／競合批判／不安を過度に煽る表現。
